# FollowUp 三端全流程人工联调操作手册

## 1. 文档目的

本文用于在当前模拟环境中，人工验证 FollowUp 云端、DMZ 和医院内网 DataSync 的完整数据同步链路，包括：

- FollowUp 云端生成数据包。
- 云端 SSH Gateway 提供数据包。
- DMZ 进行两跳 SSH 流式转发。
- CYYY 查询并拉取数据包。
- LHYY 验签、解密、备份并导入数据。
- CYYY 将导入回执转发至 FollowUp 云端。
- 重复拉取、重复导入和重复回执的幂等验证。

> [!important] 首次 v3 部署
> 首次验收从新的 `Baseline` 开始。Baseline 必须满足 `followup-hospital-sync.v3` 且 `previousPackageId` 为空，但不要求 `sequenceNo=1`。旧 v2 数据包不得导入。只有 Baseline、NTCare 展示和 ACK 闭环全部通过后，才继续验证 Incremental。

### 1.1 首次部署后的执行顺序

1. 关闭云端定时生成、CYYY 定时拉取和 LHYY 自动导入。
2. 检查六个容器、两个管理页面、云端 Web/Gateway 及版本：v3 / 1.2.0，并确认医院端拒绝旧 v2 包。
3. 恢复 Cube 模拟库并确认其既有 `form.vector` 与患者范围映射结构；仅在 DataSyncDb 执行 `20260811.sql`，不得对 CubeDb 执行 `20260722.sql`、`20260810.sql` 或其他自定义 DDL。存量升级另运行一次患者映射迁移工具。
4. 保存恢复后初始备份，按四包顺序完成三端统一初始化并执行三端“一键验证”，再在 CYYY 执行连接诊断。
5. 云端手工生成 Baseline；CYYY 手工拉取；LHYY 人工确认并导入。
6. 导入后重启 NTCare 或执行既有缓存刷新，在患者管理核对患者基础信息和合格表单。
7. 核对目标适配、CYYY `Forwarded` ACK 和云端 `Imported` 状态。
8. 制造状态晋级或新增无表单患者，生成并导入 Incremental，检查前驱、增量和幂等。
9. 完成错误 Token/密钥/篡改包拒绝验证后，再按云端授权 → CYYY 定时 → LHYY 自动导入 → 云端定时的顺序开启自动模式。

## 4. 完整人工联调步骤

在 PowerShell 执行：

- `followup-lab-cloud-tunnel`
- `followup-lab-cube-db`

验收记录：

- [ ] DMZ 容器健康。
- [ ] DataSync 管理数据库健康。
- [ ] Cube 目标数据库健康。

### 4.2 准备一条可识别的测试数据

为了验证不仅“包走通了”，而且业务数据确实同步，建议在 FollowUp 调试环境中：

1. 找一条明确的测试患者或测试业务记录。
2. 修改一个可逆字段，例如备注、测试标签或名称末尾增加“联调测试”。
3. 记录业务表名称、数据主键、修改前内容、修改后内容和修改时间。
4. 确认对应业务表在云端“备份表清单”中处于启用状态。

> [!warning]
> 不要使用物理删除测试。本同步方案不会在目标数据库执行物理删除。删除、作废和审核等业务变化应通过状态字段验证。

如果本次只验证传输与状态闭环，也可以跳过本步骤，但无法证明业务数据内容已经发生变化。

验收记录：

- [ ] 已选择可逆的测试数据。
- [ ] 已记录表名和主键。
- [ ] 已记录修改前后内容。
- [ ] 对应业务表已加入备份表清单。

### 4.9 手工校验并导入

对新包点击“校验 / 导入”。

增量包不需要基础包确认。系统会依次执行：

1. 外层文件大小和 Hash 校验。
2. 云端签名验证。
3. RSA 密钥解包。
4. HMAC 校验。
5. AES 解密。
6. 内层文件校验。
7. 包链校验。
8. 目标数据库结构检查。
9. 导入前数据库和附件备份。
10. 数据及附件导入。
11. 生成导入回执。

预期状态可能依次显示：

```text
正在校验 → 正在备份 → 正在导入 → 已导入
```

结构列应显示“兼容”。

> [!warning]
> 如果显示“需要映射”或“不兼容”，不要强行继续，应先检查结构差异。`RequiresMapping` 需要保存映射决定；`Breaking` 需要先升级数据库或导入器。

验收记录：

- [ ] 完整性和签名校验成功。
- [ ] 包链校验成功。
- [ ] 结构检查为“兼容”。
- [ ] 导入前备份成功。
- [ ] 最终状态为“已导入”。

#### 4.11.1 验证同一自然人合并

准备独立的测试患者，分别验证以下场景：

1. 云端与院端 `unique_patient.id` 相同时，继续按 ID 处理。
2. ID 不同、双方身份证号都非空且忽略首尾空格和 `X/x` 大小写后相同时，复用院端 `unique_patient`。
3. 任一方身份证号为空，双方完整的姓名、出生日期、性别都相同时，复用院端 `unique_patient`。
4. 双方身份证号都非空但不同时，不得退回三要素匹配。
5. 同一医院、课题下已有唯一 `patient` 时，包内患者事件、住院、门诊和动态表记录都应指向该院端 `patient.id`，院端现有患者字段不被云端覆盖。
6. 同一判定条件命中多条 `unique_patient`，或院端同一患者范围存在多条 `patient` 时，整包应进入 `ImportFailed`，错误码为 `PATIENT_IDENTITY_CONFLICT`，且错误信息不包含姓名或身份证号。
7. 再导入后续 `Incremental` 或重试包，即使包内没有 `patient` 行，也应按持久映射指向原院端患者。

可在 DataSyncDb 执行以下只读 SQL 核对映射：

```sql
SELECT hospital_code, source_patient_id, target_patient_id,
       source_unique_patient_id, target_unique_patient_id, identity_match_basis
FROM lhyy.followup_patient_identity_map
ORDER BY updated_at DESC
LIMIT 20;
```

验收记录：

- [ ] ID、身份证号和三要素三种匹配路径符合规则。
- [ ] 院端已有患者被复用，现有字段未被覆盖，所有关联表指向正确。
- [ ] 冲突场景整包失败且无患者隐私泄漏。
- [ ] 后续包稳定复用原映射。

验收记录：

### 4.13 在云端确认 ACK 闭环

回到 FollowUp 云端“医院数据管理”，点击“刷新”。

检查两个位置：

1. “数据包”页签中新包的 ACK 状态。
2. “回执”页签中新包的回执记录。

预期结果：

- ACK 状态为 `Imported`。
- 包号与本次测试包一致。
- AckId 有值。
- 设备标识正确。
- 收到时间有值。
- 错误信息为空。

完整链路如下：

```text
FollowUp 生成包
    ↓
云端 SSH Gateway
    ↓
DMZ 流式转发
    ↓
CYYY 拉取落盘
    ↓
LHYY 校验、备份、导入
    ↓
CYYY 转发 ACK
    ↓
DMZ
    ↓
FollowUp 收到 Imported ACK
```

验收记录：

- [ ] 云端数据包显示成功 ACK。
- [ ] 云端回执列表存在目标包记录。
- [ ] AckId、设备和时间正确。
- [ ] 错误信息为空。

### 4.14 验证重复操作幂等性

#### 4.14.1 重复拉取

在 CYYY 对该包点击重新拉取。

预期结果：

- 仍然是同一个包号。
- Hash 和大小不变。
- 管理表中不会产生第二条同包号记录。
- 状态仍为“已拉取”。

验收记录：

- [ ] 重拉后包号、Hash 和大小不变。
- [ ] 未产生重复管理记录。

#### 4.14.2 重复导入

刷新 LHYY 页面。

预期结果：

- 新包状态为“已导入”。
- “校验 / 导入”按钮禁用。
- 页面不能再次触发导入。
- 即使旧页面状态未刷新，服务端也会重新查询数据库并拒绝重复执行。

验收记录：

- [ ] 已导入包按钮禁用。
- [ ] 无法重复执行数据和附件导入。

#### 4.14.3 重复 ACK

等待 CYYY Worker 再次扫描或重启 CYYY。

预期结果：

- 云端不会产生业务上的重复成功处理。
- 已成功的 `Imported` 状态不会被失败回执降级。
- 稳定 AckId 保持不变。

验收记录：

- [ ] ACK 重试保持幂等。
- [ ] 成功状态未被降级。

## 5. 定时拉取单独验证

手工闭环通过后再测试定时模式。

### 5.1 设置定时拉取

1. 在 CYYY 选择医院来源。
2. 将“检查间隔”临时设置为 `1` 分钟。
3. 打开“启用定时拉取”。
4. 点击“保存配置”。
5. 确认页面状态显示“定时拉取已启用”。

当前 CYYY 全局自动拉取服务已经启用，因此来源开关保存后可以生效。

### 5.2 生成第二个测试增量包

1. 在云端再次点击“手动生成”。
2. 记录第二个新包号。
3. 不点击 CYYY 的“查询并拉取”。
4. 等待约 30～90 秒并刷新 CYYY 页面。

预期结果：

- 新包自动出现在 CYYY 列表。
- 拉取状态自动变为“已拉取”。
- 云端拉取次数和最近拉取时间更新。

> [!note] 定时语义
> Worker 每 30 秒扫描一次；达到页面配置的滚动间隔后执行。它不是每天固定钟点，实际执行时间还会受到扫描周期和其他医院拉取任务耗时影响。

### 5.3 LHYY 自动导入说明

LHYY 自动导入当前由容器配置 `FollowUpPackageImport__Enabled` 控制，页面只显示自动导入状态。建议本轮保持关闭，继续手工导入，避免基础包或异常结构包未经人工确认。

验收记录：

- [ ] CYYY 来源定时开关保存成功。
- [ ] 新包在未手工点击的情况下自动拉取。

## 7. 异常处理原则

出现异常时按当前阶段停止，不要越过失败环节继续操作：

| 异常阶段 | 处理原则 |
|---|---|
| 云端生成失败 | 保留生成日志，不执行拉取；检查表清单、附件引用、结构和单包大小限制 |
| CYYY 连接失败 | 检查 SSH 私钥、known-hosts、Token、医院编码、DMZ 和云端 Gateway |
| 拉取失败 | 保留包号和错误码；自动扫描会从包首重试本地失败包，不拼接中断文件，也可在页面指定包号手工重拉 |
| LHYY 完整性校验失败 | 不得进入备份或导入；检查 Hash、签名、HMAC、密钥和包文件 |
| 结构需要映射 | 保存人工映射决定或等待数据库升级，不得猜测字段映射 |
| 导入失败 | 不导入后续主链包；保留包、staging、备份和日志 |
| ACK 转发失败 | 不重复导入数据；由 CYYY 使用相同 AckId 重试转发 |
| 恢复失败 | `RestoreFailed` 会阻断 Worker 领取所有后续包；保持失败状态，停止后续导入并转人工处置 |
