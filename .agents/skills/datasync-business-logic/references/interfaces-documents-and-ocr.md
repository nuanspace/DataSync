# 医院接口、文档、文件与 OCR

## 项目文档

医院接口文档由 `ProjectDocumentService` 和对应页面/API 管理，用于配置和实施参考。文档说明的是外部契约，是否已完整实现必须再核对当前接口配置、Controller 和处理器。

典型契约：

- 世纪坛数据服务：REST/JSON，先获取 Token，再以 `serverCode`、条件、排序和分页查询；CYYY 的 `DataLakeClient`、数据湖配置和 `dl_*` 数据池承担采集。
- 嘉和生命体征：SOAP 1.1，操作 `VitaInterface`，`INPUTPARA` 内为 XML；建议转为内部 JSON 后使用题目/子卡回写和待身份绑定。
- 嘉和移动医护评估单：SOAP 1.1，操作 `MOBILEASSESSMENT`，包含患者身份、评估时间、总分、风险和循环评估项；与生命体征可共享服务代码但使用不同操作和 SOAPAction。
- 世纪坛无纸化：涉及 PDF、CA、归档标记、报告数量和查询。现有文档管理和 ESB 能力不代表所有归档动作均已实现，新增前必须定位具体适配器。

## OCR 处理

`DataSync.Common` 提供 `IOcrConversionService` 和标准 OCR 结果模型；输入支持文件路径、URL 和 Base64 PDF，结果包含全文、页面、带坐标文本块、抽取字段和元数据。

运行链路：

1. Linux 容器通过 `pdftoppm` 渲染 PDF，再由 `tesseract` 识别；运行时不下载训练数据。
2. LHYY 仅在接口配置为自定义处理器且名称匹配 `OcrMessageProcessor` 时执行 OCR。
3. 配置主记录数组时，ESB 先把数组记录拆成独立消息；OCR 从当前主记录读取 PDF 并把结果挂到该主记录的 `Ocr` 节点。没有主记录数组时仍挂到消息根节点，然后复用 `GenericMessageProcessor` 和既有字段映射。
4. CYYY 主动采集 PDF 时只负责传递路径、URL 或 Base64；OCR 与 ntcare 写入仍在 LHYY。

接口配置页不向业务配置人员暴露识别语言、DPI、PSM、超时、临时文件、坐标和正则表达式。运行时固定使用中英文、300 DPI、自动页面布局和单页 180 秒超时；未单独配置限制时默认最多处理 20 页、20 MB 的 PDF。识别图片最长边超过 3500 像素时只按比例缩小该页，并关闭表格结构分析，避免异常页面长期占用识别进程。处理完成后清理临时文件；缺少指定语言组件时即使 Tesseract 返回成功也按识别失败处理，禁止静默退化为单一语言。页面仅配置 PDF 来源、样本和需要提取的字段；每个字段包含输出字段名称、PDF 字段名称、可选所属标题、可选识别说明和必填性，不依赖用户框选或坐标配置。输出字段名称是 `Ocr.ExtractedFields` 的 JSON Key；PDF 字段名称必须与报告字段文字一致，只容忍标题周围空格、标题和值之间的换行及中英文冒号。旧规则加载时以原字段名称同时补齐输出字段名称和 PDF 字段名称。系统内部对普通字段使用 Tesseract 文字坐标，只向模型提供字段名右侧最近的一组文字及无其他标题的紧邻续行，遇到明显列间距即截断；PDF 表格中存在同名字段时，每条规则必须配置不同的所属标题，并由固定版式识别先限定标题所在列再定位字段和值。字段和值不能唯一确认在同一局部区域时返回 `null`，不得从报告其他位置选取恰好存在的数值。识别说明只能限定值的提取范围，不能充当字段别名或所属标题。系统先用 Tesseract 识别整份 PDF，再使用全局配置中当前生效的 LLM 从 OCR 原文提取已配置字段；每次调用按当前字段动态生成严格 JSON Schema，通过 OpenAI 兼容接口的 `response_format` 限制输出只能包含配置字段且值只能为字符串或 `null`。响应解析兼容纯 JSON、Markdown 或说明文字包裹的 JSON、`message.parsed` 及分段 `content`，但最终内容仍必须是符合字段约定的 JSON 对象。全局选择线上模型时 OCR 原文会发送到对应线上提供方，选择本地模型时发送到本地服务。不记录 PDF Base64、OCR 原文、患者字段值或模型原始响应。OCR 普通日志只记录页数、配置字段数量、耗时、分块数量、失败类型及必填但未识别的字段名称。模型只能引用报告原文，不得推断、纠错、总结、翻译、换算或标准化。配置仍按事件代码和接入项目保存到 `esb_ocr_profile`，字段规则继续使用原有 JSONB，不新增平行配置表。

OCR 接口至少配置一个字段，页面保存、快速启用、配置同步导入和正式处理都执行相同校验，零字段配置不能启用或处理。正式输出固定为 `Ocr.Mode=Fields`、`PageCount` 和 `ExtractedFields`，只输出已配置字段，忽略模型额外字段，不输出全文、坐标文字块、图片或运行元数据。每个字段只能是一个保留原文内部换行的字符串、空字符串或 JSON `null`，模型返回数组或其他结构时按结果格式错误处理；长报告分块提取时按 PDF 顺序保留第一个通过原文证据校验的标量结果，不合并后续结果。非空值必须能在未加入页码等系统文字的纯 Tesseract 原文中找到，空字符串只在原文存在同名字段标题时接受；未匹配为 JSON `null`。必填字段未识别或内容为空时消息失败；非必填字段未识别时继续，即使全部非必填字段均为 `null` 也不因 OCR 字段缺失而失败。OCR 失败、全局当前 AI 不可用、AI 返回非法 JSON或结果无法解析时消息失败并进入既有重试链路。字段映射读取 JSON `null` 时按缺值处理，未配置默认值则不写入；映射工作台不另建 OCR 专用映射体系。病案号来自 PDF 时，将“病案号”作为 OCR 字段，并把接口现有 `MrnSourcePath` 配置为 `$main.Ocr.ExtractedFields.病案号`，患者匹配逻辑不另行扩展。

接口配置页可按当前事件代码、当前尚未保存的识别规则和 `ServerCode` 读取已有消息作为 OCR 样本，也可从消息详情页快捷进入。OCR 配置只保存样本消息编号，不复制 PDF；再次编辑时直接展示已保存的字段配置。主编辑弹框中的字段区域只展示可滚动的字段摘要列表；新增和编辑共用同一个高层级批量配置弹框，可在一次打开期间连续新增、修改或删除多条规则，确定后统一应用到接口草稿。样本不存在时仍可新增、编辑、删除并保存字段，只是不能查看 PDF 或测试结果。有样本时，用户明确点击“查看 PDF 并配置字段”后才执行只读 OCR；首次只渲染并识别前 3 页，后续页面不在后台自动处理，由用户点击“加载更多（3页）”逐批追加。左侧按原始版式显示已加载页面并支持翻页、缩放，右侧可新增、编辑、删除字段且字段列表始终独立滚动，不提供框选。用户可随时基于当前已加载页面测试字段，未加载页面中的字段暂时返回 `null`；追加页面后旧测试结果立即失效，需要重新测试。点击“测试全部字段”复用当前已加载页面的 OCR 文字调用全局当前 AI，不重新转换已加载页面。分批加载失败时保留此前已加载页面并允许重试当前批次。样本测试不调用正式消息处理器，不执行字段映射或业务表写入，不修改消息状态，也不要求先匹配患者。AI 调用失败时保留 PDF 和字段配置并显示错误，不能把未执行测试的初始化字段显示为“未识别到”；只有 AI 成功执行后未提取到的字段才显示 `null`。PDF 预览弹框可以复用接口保存校验和事务直接保存整个接口，保存成功后保持预览打开。保存 OCR 接口时重建 `SampleJson` 中的 `Ocr.ExtractedFields`：当前样本和字段取值规则均未变化且没有重新测试时保留已有模板值；最新测试与当前样本、字段规则完全对应时使用测试值；样本或字段取值规则变化后尚未重新测试时写入 `null`。只改变必填性不使已有测试值失效，删除或改名字段后同步移除旧 Key。仅打开、查看或关闭 PDF 预览不改变消息模板已有值。模板会移除 PDF Base64、预览底图和大段文本。正式消息处理仍识别配置范围内的整份 PDF，不受样本分批预览影响。OCR 接口只能使用入队异步处理；停用接口仍可编辑和预览。配置同步将 OCR 配置和字段规则随接口一起迁移，但不携带环境相关的样本消息编号。

包含 Base64 等大文本的消息详情仅生成一次省略大文本的安全预览；树形查看按需解析原始 JSON，并限制长字符串、节点和数组的页面渲染。该限制只作用于页面展示，OCR、接口配置样本、字段映射和正式消息处理仍读取数据库中的完整原始消息。

## HTML 医疗文书处理

LHYY 在接口配置为自定义处理器且名称匹配 `HtmlMessageProcessor` 时，将当前主记录中配置路径指向的 Base64 文本转换为结构化 JSON，再复用 `GenericMessageProcessor`、既有字段映射和患者事件定位链路。批量响应仍由 ESB 的 `MainRecordArrayPath` 先拆成独立消息；根数组拆分后的单记录数组也受支持。

HTML 配置按事件代码和接入项目保存在 `esb_html_profile`，包含 Base64 来源路径、最大解码字节数、是否保留章节、章节标题和确定性字段规则，并随接口配置同步迁移。接口配置页仅在选择 `HtmlMessageProcessor` 时展示该配置，不改变其他 Custom、OCR 或 Generic 接口。

运行时在完整分配前估算 Base64 大小，解码后优先使用严格 UTF-8；UTF-8 失败时使用严格 GB18030，两者均失败则消息失败。处理器最多执行三轮 HTML 实体解码，统一 `<br>` 等换行，删除行尾空格及所有非空行共有的基础缩进，但保留空格表格各行的相对缩进和空列，再按配置标题切分章节，并使用完整章节、标题值、生命体征、诊断列表、空格表格或受超时保护的正则规则提取细字段。标题值只读取标题所在行，冒号后到行尾没有内容时输出 JSON `null`，不得跨行借用下一标签和值；手工候选发现使用相同边界。该链路不调用 LLM，不总结、纠错、翻译或标准化原文。

正式输出挂到当前主记录的 `Html` 节点：`Html.Mode=Fields`、`Html.Sections` 和 `Html.ExtractedFields`。字段值只允许为保留原文的字符串或 JSON `null`；诊断等多值按原顺序用换行连接，以复用现有标量字段映射。任一必填规则未命中时消息失败并进入既有重试链路，非必填规则未命中写入 `null`。不生成永久 txt 文件，不在普通日志中记录 Base64、正文、章节或患者字段值；日志只记录文本长度、编码、章节数、字段数、耗时和失败类型。

接口配置页的 HTML 区域提供手工测试：可粘贴完整医院响应 JSON（对象或数组）或单独的 `FILE_CONTENT` Base64，并使用当前尚未保存的 HTML 草稿配置调用同一个 `HtmlTextExtractionService`。尚未配置细字段时也允许执行解码、正文清洗和章节预览，但正式保存、启用和消息处理仍要求至少配置一个提取字段。JSON 输入通常按当前 `MainRecordArrayPath` 和 Base64 来源路径逐条测试；为兼容现场直接复制 FBC-027 原始响应，配置的组合路径未命中根数组或单条根对象时，手工测试可回退把根记录作为测试记录，并仅在配置来源路径未命中时读取该记录根级的 `FILE_CONTENT`。该回退不进入正式 `HtmlMessageProcessor`；应用候选字段时优先保留与正式主记录路径匹配的既有组合消息模板，避免被原始 FBC-027 数组覆盖。单条失败不阻断其他记录，单次最多处理 100 条；结果展示清洗文本、`Sections`、`ExtractedFields`、必填缺失、编码、长度和耗时。测试结果可以把章节及清洗文本中的“标题：值”候选合并到当前细字段规则，同名字段保留现有配置，并同步生成含 `Html.Sections`、`Html.ExtractedFields` 的脱敏消息模板，供接口映射工作台选择路径。以上操作只更新当前页面草稿，不创建 ESB 消息、不执行过滤映射或业务写入、不修改消息状态；只有外层保存才持久化配置，关闭或清空仍会移除测试输入和结果。

## 文件和网络安全边界

- 文件路径必须在配置的 `allowed_file_roots` 内；既做字面预检，也解析已存在路径的 symlink/junction 最终目标。
- URL 必须为 `http/https` 且命中允许主机；每次请求和重定向都重新校验目标 IP。未配置 CIDR 时拒绝 loopback、私网、link-local、保留和多播地址。
- 禁用自动重定向并限制跳转次数；不得通过 30x 绕过主机/IP 白名单。
- Base64 在分配完整字节数组前按编码长度估算大小。
- 外部命令使用参数列表传参；超时时终止进程树，并限制终止后的等待时间。
- OCR 输出路径必须在 `AllowedOutputRoots` 中，文件名需包含消息身份、时间和随机后缀，避免并发覆盖。
- OCR 顶层输入要求 JSON 对象；不把顶层数组失败悄悄转成成功。
- 原始报告、OCR 文本和患者标识不得进入知识文档或普通日志。

## 归档与附件

- PDF、DOC、DICOM、CA 和归档状态属于外部协议的一部分；明确传输方向、大小限制、校验、幂等、存储生命周期和失败重试后再实现。
- 附件的可读 URL、容器挂载和物理目录必须作为同一链路验证，不能只验证数据库字段存在。
- FollowUp 医院包附件另受包清单、checksum、医院范围、备份和恢复约束，参见 `followup-hospital-sync.md`。

## 变更检查

外部接口字段、SOAPAction、文件来源、白名单、OCR 输出结构或归档状态改变时更新本文件。现场地址、凭据和患者样本只放安全配置或本地忽略证据，不写入知识库。
