# 数据库运维、发布边界与已知风险

## 数据库升级分类

- `init_database.sql` 与 `Scripts/**.sql` 是功能脚本，按原顺序执行，执行前备份。
- `DatabaseUpgrades/**.sql` 是专项优化脚本，不进入常规功能升级链。
- 同一天 LHYY 数据库变更追加到 `Scripts/yyyyMM/yyyyMMdd.sql`；CYYY 遵循其 `Migrations/yyyy-MM/` 规则。
- `db-upgrade` 命令仅检查内置脚本，不绕过页面状态和确认机制执行升级。
- FollowUp 患者身份合并禁止对 CubeDb 执行自定义 DDL。维护窗口内只在 DataSyncDb 执行 `20260811.sql`，启动兼容检查仅验证 CubeDb 既有患者身份字段读权限和包内业务表权限；存量旧映射通过显式工具以 CubeDb 只读事务迁移，工具无法恢复历史时改走 `RecoveryBaseline`。
- CubeDb 的 vector 扩展是按需能力：`CubeCompatibility:RequireVectorExtension` 默认关闭，缺失时启动兼容检查只告警；明确启用向量能力时必须打开并作为失败项。逐包 schema/字段类型检查仍拒绝不兼容的 vector 字段，不能用默认放宽替代包级校验。

## 优化任务安全模型

- `DatabaseUpgradeService` 的托管后台队列承担长任务；页面轮询阶段和有限日志，不把内存进度当作长期审计。
- 状态文件只保存连接指纹、脚本路径/hash 和执行状态，不保存密码；采用同目录临时文件后替换。
- 状态文件不可写时禁止优化脚本执行和人工标记，但功能脚本仍遵循自身流程。
- 同一目标库同一时间只允许一个升级操作；登记按精确 ID 释放，真正执行前重新确认脚本状态。
- 应用停止时传递取消信号，数据库事务回滚，外部 `pg_dump/psql` 终止进程树；advisory lock 释放不得被取消打断。
- 数据库动作完成但状态补写失败时明确报告“不确定的记录状态”，不能把已执行动作反向标记为失败并自动重跑。

## ESB 消息归档

- 专项归档项包括结构升级、历史终态消息迁移和验证，不等于只执行一份 SQL。
- 状态优先由目标库结构和待迁移数据判断；结构不完整或检测失败为未知，不能手工猜测。
- 迁移进度和本轮计数属于任务运行数据，只在当前任务展示，不写入长期知识库。

## 医院端离线交付边界

- `deploy/s7-followup-hospital` 是模板，不是可直接交付的成品目录；使用 `datasync-offline-release` 的发布流程。
- 交付包只允许白名单文件、四个镜像、两个仅结构基础库 dump 和实施文档，并生成/回验 `manifest/SHA256SUMS.txt`。
- 基础 dump 必须用 `pg_restore --list` 拒绝表数据、序列值和大对象数据。
- 发布环境只从指定环境文件读取；不得继承同名调用进程变量作为隐式兜底。
- 文档、配置、secrets 说明和数据库文件使用明确白名单；拒绝符号链接、隐藏路径、特殊文件和输出目录嵌入输入目录。
- 镜像归档名包含稳定序号，避免名称清洗碰撞。

## 当前需复核的风险

- CYYY 未匹配消息、任务启用状态和 `serverCode/tranCode` 对齐必须从当前数据库和报文核对，不沿用历史数量。
- 推送类型与目标格式不一致时，在启用前核实任务记录和实际推送实现。
- PDF、CA、归档等文档契约不代表完整实现；按具体入口和处理器确认。
- 配置文件可能含环境密钥；读取可以用于本地分析，任何输出必须脱敏，不把值复制到文档。
- FollowUp 恢复、CubeDb 运维和附件存储是高风险边界，必须保留确认、备份、锁、恢复证明和实际端到端验收。
- 患者身份冲突必须失败关闭；错误和日志只记匹配规则、标识和候选数，不记录姓名或身份证号。本变更不对历史重复数据执行物理合并或清理。

## 知识与日志保留

- 长期知识只写稳定行为和安全理由；Git 记录“改了什么”。
- 本地任务日志、截图、构建输出和验证证据放 `.codex/artifacts/`，由外部清理策略保留最近 10 次或 14 天。
- 患者样本、连接串、密钥和现场地址不进入仓库。
